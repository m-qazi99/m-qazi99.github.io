Why row counts are not enough for CSV reconciliation

A practical guide to business keys, missing records, Decimal tolerances, and reconciliation evidence using Recon Lab.

By Muzammil Qazi · Published 2026-10-20 · Independent portfolio demonstration

Equal row counts can conceal different records

A source and target can each contain three rows while disagreeing on which business keys exist and which values belong to those keys. Row counts are a starting signal; they do not establish source-to-target equality.

Recon Lab makes those differences inspectable. It indexes unique business keys, compares selected fields, and distinguishes changed values from missing and target-only records. Composite keys are supported when a single column is not unique.

A small example with four distinct outcomes

Consider these synthetic snapshots:

Source

id,amount
1,10.00
2,20.00
3,30.00

Target

id,amount
1,10.02
2,22.00
4,40.00

Using id as the key and an absolute amount tolerance of 0.05 produces one matching record (key 1), one changed record (key 2), one missing record (key 3), and one target-only record (key 4). Both files have three rows, yet most of the records require attention.

Tolerance is a business policy

The Python engine compares numeric values using Decimal arithmetic. A field matches when its absolute difference is no greater than the larger of the absolute tolerance and the source-relative tolerance:

abs(source - target) <= max(absolute_tolerance,
    relative_percent / 100 * abs(source))

For example, a source value of 100 and target value of 110 match at a 10% source-relative tolerance. That does not mean a ten-unit difference is acceptable for your business process. The policy must match the unit, precision, and intended use of the field.

Text comparison is exact unless trimming and case folding are explicitly enabled. A numeric tolerance cannot fix a missing key. Duplicate or blank keys are rejected because they make a one-record-to-one-record comparison ambiguous.

Investigate exceptions, then inspect totals

Use the record inspector to see source and target values beside the field-level difference. The tolerance frontier shows how changing an absolute threshold alters matching coverage under the current text and relative policies. Control totals can reveal aggregate changes, but equal aggregates can still hide offsetting differences or missing keys.

The application exports an exception ledger and comparison policy. It does not alter either input. A reproducible handoff should retain the chosen keys, compared fields, tolerances, normalization rules, and exceptions.

Inspect the Python implementation, the boundary tests, and the live experiment. These are independent portfolio examples, not claims about employer data or achieved reconciliation accuracy.
