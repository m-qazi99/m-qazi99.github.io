Data quality and reconciliation answer different questions

A CSV can pass a not-null contract and still omit an expected customer. Conversely, two snapshots can agree while both contain the same invalid value. DataLens evaluates rules about records; Recon Lab evaluates agreement between records. A complete investigation may need both.

A synthetic investigation you can reproduce

  1. Open Pipeline Pulse to inspect which assets a failed dependency blocks. A blocked downstream asset is an effect, not automatically another root cause.
  2. Use DataLens with a synthetic CSV to inspect nulls, duplicate values, ranges, and the rules chosen for that dataset.
  3. Use Recon Lab with two snapshots to distinguish absent business keys from changed fields. Keep the selected keys and tolerance policy with the exceptions.
  4. Use Runbook Radar to retrieve relevant notes and inspect the source passage. Relevance is not permission to execute a change.
  5. Use Privacy Forge on a synthetic extract to examine column policies and remaining signals before considering a sharing workflow.

The apps are separate experiments. There is no automatic connection to cloud services or cross-app transfer of your input. Use their exports to retain the evidence you choose to inspect.

What to inspect in a technical review

Start with the implementation pages, follow each source repository, run the supplied synthetic examples, and inspect the tests at policy boundaries. Ask whether the stated limitations match the decisions the code makes. The public work demonstrates inspectable implementation choices; it does not establish client outcomes or production scale.
